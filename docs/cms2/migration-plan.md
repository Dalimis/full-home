# 資料遷移與回復計畫

> 原則：遷移**只讀取**舊 D1 與舊 R2，不修改、不刪除。舊 Worker 與舊資料在新系統穩定運作至少 30 天前完整保留。

## 1. 遷移步驟

| # | 步驟 | 做法 | 產出 / 檢查點 |
|---|---|---|---|
| 1 | 備份 D1 | `npx wrangler d1 export fullhome-cms-db --remote --output=backup/d1-YYYYMMDD.sql` | SQL 檔存到 NAS 與另一個 R2 bucket；記錄 Time Travel bookmark |
| 2 | 備份 R2 | 用 rclone（S3 相容）把 `fullhome-files` 同步到 NAS | 物件數、總大小、每個檔案的 ETag 清單 |
| 3 | 盤點 | 匯出各表筆數、欄位；R2 物件與 `documents.file_key` 比對 | 找出孤兒檔案、缺檔紀錄（遷移前先修正或標記） |
| 4 | 建立新 Schema | Payload：由 `payload.config.ts` 產生 migration；Directus：用 schema snapshot | 在**測試環境**套用 |
| 5 | 設定 Collections 與角色 | 依 architecture.md 第 4 節 | 權限測試清單 |
| 6 | 轉換並匯入 | 寫一支匯入腳本：讀舊表 → 轉換（例如年度統一為民國年）→ 透過 CMS API 寫入 | 腳本可重複執行（以 `legacyId` 去重） |
| 7 | 建立新舊 ID 對照 | `documents.legacyId` 欄位 + `legacy_file_map(old_id, new_id, r2_key)` | `/files/{old_id}` 的相容依據 |
| 8 | 檢查檔案與連結 | 逐一 HEAD 測試新舊 `/files/*`；比對 Content-Type、大小 | 失敗清單 = 0 |
| 9 | 比對資料 | 舊/新筆數一致；關鍵欄位逐欄比對（公司資料全部、董事姓名/類型/排序、文件標題/分類/年度/公開狀態） | 差異報告 |
| 10 | 前台 API 相容測試 | 用同一組測試比對新舊 `/api/public/investors` 的 JSON 結構與內容 | 前台在測試網域完整走過一次 |
| 11 | 切換策略 | 見第 2 節 | — |
| 12 | 正式切換 | 經你確認後才執行 | 驗收清單 |

### 檔案遷移細節
- **不搬檔案**：舊檔案留在原本的 R2 key，新 CMS 的文件紀錄直接指向原 key。省時間，也不會有複製失敗的問題。
- 新上傳的檔案放 `cms/` 前綴，與舊檔案分開。
- 匯入腳本的失敗重試：每筆獨立處理、記錄結果；失敗的寫入 `migration-errors.json`，修正後重跑（以 `legacyId` 判斷是否已匯入，不會重複）。

## 2. 切換策略：短暫唯讀

資料量很小（董事 8 筆、文件 1 筆），不需要增量同步。

1. 公告編輯同仁：切換期間（約 30 分鐘）暫停修改後台。
2. 舊 Worker 設定 `READ_ONLY=true`，所有 admin 寫入回 503。
3. 重新執行匯入腳本（只會補上差異）。
4. 跑第 1 節的第 8–10 步驗證。
5. 修改 `wrangler.jsonc`：把 `/api/public/*`、`/files/*` 路由改指向新的公開 Worker → commit → 自動部署。
6. 監控 24 小時：錯誤率、`/files/*` 404 數、表單寄送。

## 3. 回復方案

| 情境 | 回復方式 | 時間 |
|---|---|---|
| 切換後前台資料異常 | `git revert` 路由變更的 commit → 自動部署，路由回到舊 `fullhome-cms` | 約 2 分鐘 |
| 切換後才發現資料錯誤 | 同上；舊 D1 在切換期間是唯讀，資料仍是切換前的狀態 | 約 2 分鐘 |
| 新 CMS 運作一段時間後要回退 | 用匯出腳本把新 CMS 的資料寫回舊 D1（需事先寫好並測試） | 半天 |
| 舊 D1 意外被改壞 | `wrangler d1 time-travel restore`（**原地覆寫**，先匯出現況再還原），或從步驟 1 的 SQL 檔重建 | 30 分鐘 |
| R2 檔案遺失 | 從 NAS 備份還原該物件 | 依數量 |

**回復演練**：正式切換前，在測試環境實際跑一次「切換 → 回復」，確認上表的時間與步驟可行。

## 4. 正式切換前驗收清單

- [ ] 官網首頁、投資人 8 頁正常顯示
- [ ] 既有 `/files/{id}` 全部可下載，Content-Type 正確
- [ ] 隱藏或未發布的資料，匿名請求拿不到（API 與 `/files` 都測）
- [ ] 非管理員呼叫管理 API 被拒（未登入、已登入但無權限各測一次）
- [ ] 能在後台新增一個測試集合與欄位，並由公開 API 讀到
- [ ] D1 與 R2 備份完成，且已實際還原一次到測試環境
- [ ] 部署與維運文件完成（README、回滾步驟）
